# Budget and live collector validation

- Diagnose stale weekly budgets by checking the cron's `script` and `no_agent` together: a prompt containing write instructions cannot update a file when only a report script executes. Require an atomic file publication plus read-back and explicit target/source-week fields; cron `ok` is not freshness.
- Stage repairs outside active scripts and cron definitions; preserve exact production-to-staged unified diffs and source hashes. Exercise publication against an alternate scratch output, never the active budget file during read-only smoke.
- Confirm the business definition of GMV from the controlling rule; gross sales and sales-minus-returns differ. Use Decimal for money and label the basis in output.
- A campaign's current status does not describe all spend during today: include completed status 7 alongside 4/9/11, deduplicate IDs, and filter unsupported deleted/empty-product campaigns. Do not assume update timestamps prove when completion occurred.
- WB statistics may return `{"data": null}` for an old campaign batch. Continue later batches while recording absent IDs as unknown; do not turn missing rows into proven zero or declare account-wide completeness.
- Preserve sanitized failure diagnostics on stderr and explicit null totals on fatal failures. Separate collection coverage, account coverage, and incomplete-day attribution in output. A successful empty/null batch is a completed request with unknown missing IDs, not an automatic process failure; reserve exit1 for actual request/validation failures. Reports consuming numeric spend must visibly retain the unknown-account/returned-row-only qualification.
- Use a no-argument weekly wrapper with `main(budget_only=True)` for no_agent cron; the scheduler passes a literal script filename. Keep dashboard reads separate from budget publication, and test both preservation-on-error and publication/read-back. Trigger the exact job through `hermes cron run` and inspect its new last_run plus the budget source/target weeks.
- Isolate staged module imports in tests with explicit file-based importlib names: sys.path changes alone can silently test a production module already present in sys.modules.
