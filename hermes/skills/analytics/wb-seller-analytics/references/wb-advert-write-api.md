# WB advertising write paths

## Канонические названия и проверка ответов

- Для новых РК используй формат Максима `П004…_модель_тип_вариант/DD.MM`, например `П00447927_Вико_Тахта_Parma_6/11.09`. Сохраняй код 1С и различающие модель/размер/цвет; не добавляй служебные префиксы вроде «FBS-тест». Проверяй полное имя после создания.
- `wb_get_minimum_campaign_bids` принимает `placement_types=["search","recommendation"]` — recommendation в единственном числе. Создание и обновление ставок используют `recommendations`. Значения `bids[].bids[].value` уже в копейках; не умножай повторно.
- Сразу после создания minimum-bids может вернуть `request_rejected` из-за задержки появления кампании. Подожди и повтори только read-запрос; не создавай дубль.
- `sdk_error` при применении пополнения НЕ доказывает, что деньги не зачислены. Сохрани попытку в журнал, останови записи и прочитай бюджет точной РК. Если до операции было 0 и после стало ровно согласованное пополнение, эффект подтверждён; продолжай без повторного пополнения. Если результат неясен — остановись, не ретраить финансовую операцию.

Все суммы пополнения задаются в рублях. Ставки `bid_kopecks` задаются в
разменных единицах: `100` означает 1 рубль.

| Задача | Инструмент |
| --- | --- |
| Создать manual CPM кампанию | `wb_plan_update_campaign`, `action=create` |
| Запустить | `wb_plan_update_campaign`, `action=start` |
| Поставить на паузу | `wb_plan_update_campaign`, `action=pause` |
| Остановить | `wb_plan_update_campaign`, `action=stop` |
| Удалить остановленную | `wb_plan_update_campaign`, `action=delete` |
| Переименовать | `wb_plan_update_campaign`, `action=rename` |
| Минимальные ставки | `wb_get_minimum_campaign_bids` |
| Изменить ставки | `wb_plan_update_bids` |
| Пополнить бюджет | `wb_plan_deposit_campaign_budget` |

## Отбор РК по остаткам

- Для согласованного Максимом завершения по отсутствию товара используй
  условие **FBS=0 И FBO=0 по всем товарам РК**. Любой положительный остаток
  сохраняет кампанию. Отсутствующая строка или отсутствующий `stockCount` —
  неизвестное значение, не ноль. Смешанные кампании не завершай целиком.
- Показывай отдельно число кампаний и уникальных товаров, статусы active/paused,
  число исключений с положительными остатками и неполными данными.
- `wb_get_stock_products` — аналитический отчёт, а не независимая проверка
  складов продавца. Называй источник явно; повтор того же отчёта не является
  независимой сверкой. Сбой `wb_list_warehouses` не доказывает нулевой FBS.
- Перед применением заново сверь оба остатка и состав товаров для точного
  согласованного allowlist. Не расширяй список после подтверждения.
- Завершение = `action=stop`, целевой статус 7; это не pause и не delete.

## Безопасная последовательность

### Создание

1. `wb_list_campaigns` со статусами `4, 9, 11`, проверить дубли по `nm_id`.
2. `wb_plan_update_campaign`:

```json
{
  "action": "create",
  "name": "SKU_Название/23.07",
  "nm_ids": [123456789],
  "bid_type": "manual",
  "payment_type": "cpm",
  "placement_types": ["search", "recommendations"]
}
```

3. Показать confirmation ID и применить только после подтверждения в той же
   живой MCP-сессии: confirmation хранится только в памяти процесса.
4. Перечитать кампанию. Не пополнять и не запускать автоматически.

### Пополнение и запуск

1. Прочитать `wb_get_campaign_budget`.
2. Создать план пополнения с `amount >= 1000`, обычно `source_type=1`.
3. После явного подтверждения применить один раз.
4. Дождаться отражения бюджета. Задержка не является сигналом для повтора.
5. Только затем отдельно спланировать запуск.

### Пауза и удаление

Пауза допустима только после показа списка campaign ID и подтверждения.
Удалять можно только остановленную кампанию; перед применением перечитать её
статус.
